1. Descripción de la Aplicación

🏆 SportManager - Sistema de Gestión Deportiva

SportManager es una aplicación web integral diseñada para la administración de escuelas deportivas, clubes y centros de formación atlética. El sistema facilita la gestión completa de deportistas, pagos, asistencias, uniformes y reportes administrativos.

Tecnologías Implementadas

🔧 Stack Tecnológico Principal

  • Lenguaje Backend: PHP 8.1+
  • Arquitectura: Modelo Vista Controlador (MVC) Personalizado
  • Base de Datos: MySQL 8.0 con particionamiento por fechas
  • Frontend: HTML5, CSS3, JavaScript ES6+
  • Framework CSS: Bootstrap 5.3
  • Procesamiento de Pagos: PayU Latam API
  • Generación PDF: mPDF 8.0
  • Emails: SendGrid API

Justificación de la Arquitectura MVC

Se implementó una arquitectura MVC personalizada por las siguientes razones:

  • Separación de Responsabilidades: Permite mantener la lógica de negocio (Modelos), presentación (Vistas) y control de flujo (Controladores) completamente separados.
  • Mantenibilidad: Facilita la modificación y extensión del código sin afectar otros componentes.
  • Reutilización: Los modelos y vistas pueden ser reutilizados en diferentes contextos.
  • Testabilidad: Cada componente puede ser probado de forma aislada.

Herramientas de Pruebas E2E Utilizadas

🧪 Estrategia de Pruebas Seleccionada

Herramienta Principal: Selenium WebDriver con PHP

Justificación de la Elección:

  • Compatibilidad Nativa: Selenium se integra perfectamente con aplicaciones PHP
  • Multi-navegador: Permite probar en Chrome, Firefox, Safari y Edge
  • Interacción Real: Simula clics, formularios y navegación como un usuario real
  • Capturas Automáticas: Genera screenshots automáticamente en cada paso
  • Reporting Integrado: Produce reportes detallados con evidencias visuales

5. Correcciones Realizadas

Basándose en los resultados de la primera ejecución, se implementaron correcciones específicas para resolver los problemas críticos identificados.

🔧 Corrección 1: Sistema de Autenticación

❌ Error Original

Descripción: Error 404 al procesar login - ruta /login-submit no existe

Archivo Afectado: Formulario de login en app/views/auth/login.php

Síntoma: Usuarios no pueden acceder al sistema

🔍 Causa Raíz

El formulario de login hacía POST a una ruta inexistente. El sistema de ruteo no tenía configurado el endpoint login-submit.

<form method="POST" action="login-submit"> <input type="email" name="email" /> <input type="password" name="password" /> <button type="submit" name="login">Iniciar Sesión</button> </form>

✅ Solución Implementada

Archivos Modificados:

  • index.php - Agregada ruta para login-submit
  • app/controllers/loginController.php - Corregida lógica de redirección
  • app/views/auth/login.php - Actualizada acción del formulario
// index.php - Nueva ruta agregada case 'login-submit': require_once __DIR__ . '/app/controllers/loginController.php'; break; // loginController.php - Redirecciones corregidas if ($usuario) { $_SESSION["usuario"] = $usuario; header("Location: " . sm_url("dashboard")); exit(); } else { header("Location: " . sm_url("login?error=invalid")); exit(); }

🔧 Corrección 2: Integración PayU

❌ Error Original

Descripción: Error 500 en callback de confirmación PayU

Archivo Afectado: confirmar_pago.php

Síntoma: Pagos procesados pero no confirmados en el sistema

🔍 Causa Raíz

La validación de firma digital de PayU estaba usando parámetros incorrectos y la URL de confirmación no estaba configurada en el ambiente sandbox.

// Código problemático - validación incorrecta $sign = md5($apiKey.$merchantId.$referenceCode.$amount.$currency); if ($receivedSignature !== $sign) { // Rechazar pago - SIEMPRE FALLABA exit('Invalid signature'); }

✅ Solución Implementada

Archivos Modificados:

  • app/Services/PayUService.php - Corregida validación de firma
  • config/payu.php - Actualizada configuración sandbox
  • confirmar_pago.php - Mejorado manejo de callbacks
// PayUService.php - Validación corregida public function validateSignature($params) { $signature = $this->config['apiKey'] . '~' . $this->config['merchantId'] . '~' . $params['reference_sale'] . '~' . $params['value'] . '~' . $params['currency'] . '~' . $params['state_pol']; $expectedSignature = md5($signature); return $expectedSignature === $params['sign']; } // config/payu.php - Configuración actualizada 'returnUrlBase' => 'http://localhost/sportmanager', 'confirmationUrl' => 'http://localhost/sportmanager/confirmar_pago.php', 'responseUrl' => 'http://localhost/sportmanager/respuesta_pago.php',

🔧 Corrección 3: Validación de Emails Duplicados

❌ Error Original

Descripción: El sistema permite registrar usuarios con emails existentes

Archivo Afectado: app/models/User.php

Síntoma: Múltiples cuentas con el mismo email causan conflictos

🔍 Causa Raíz

La función create() no verificaba la existencia del email antes de insertar el nuevo usuario.

// Código problemático - sin validación de duplicados public static function create(array $data): bool { // Insertaba directamente sin verificar duplicados $stmt = $model->db->prepare("INSERT INTO usuarios ..."); return $stmt->execute([...]); }

✅ Solución Implementada

Archivos Modificados:

  • app/models/User.php - Agregada validación de email único
  • app/controllers/registerController.php - Mejorada respuesta de errores
// User.php - Validación agregada public static function create(array $data): bool { $model = new self(); // Verificar que el email no existe if ($model->findByEmail((string)$data['email'])) { return false; // Email ya existe } // Continuar con creación solo si email es único $stmt = $model->db->prepare("INSERT INTO usuarios ..."); return $stmt->execute([...]); } // registerController.php - Mejor manejo de errores if (!User::create($userData)) { $error = "Email ya registrado o datos inválidos"; header("Location: register?error=" . urlencode($error)); exit(); }

// routes.php - Rutas centralizadas $routes = [ 'login' => 'iniciar-sesion', 'register' => 'registro', 'dashboard' => 'panel', 'logout' => 'cerrar-sesion', 'login-submit' => 'app/controllers/loginController.php' ]; // index.php - Manejo mejorado if (isset($routes[$route])) { if (str_ends_with($routes[$route], '.php')) { require_once $routes[$route]; } else { // Redirección canónica header("Location: " . sm_url($routes[$route])); } exit; }
